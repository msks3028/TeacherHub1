# TeacherHub — منصة تعليمية خاصة بالمدرس وطلابه

مشروع Full-Stack بواجهة React وBackend مبني بـ Node.js/Express وقاعدة PostgreSQL عبر Prisma. التشغيل يحتاج إعداد قاعدة البيانات والأسرار في متغيرات البيئة؛ حالة التحقق وحدود الاختبارات موثّقة في `TEST_REPORT.md`.

## 🧱 الـ Stack

- **Frontend:** React 18 + Vite + Tailwind CSS + React Router + Axios
- **Backend:** Node.js + Express
- **Database:** PostgreSQL عبر Prisma ORM
- **Auth:** JWT (httpOnly cookie) + bcrypt، بالإضافة إلى QR Login للطلاب
- **File Storage:** التخزين المحلي هو الافتراضي (`backend/uploads/`) خلف فحوص الصلاحيات؛ يوجد دعم اختياري لـ S3-compatible عبر متغيرات البيئة.

## ميزات المنصة حسب التنفيذ الحالي

القوائم أدناه تصف وظائف موجودة في الشيفرة، ولا تعني أن كل مسار اختُبر من البداية إلى النهاية. راجع `TEST_REPORT.md` و`SECURITY_AUDIT.md` لمعرفة ما تم التحقق منه. مساعد الذكاء الاصطناعي متاح للطلاب فقط؛ أدوات AI الخاصة بالمدرس معطّلة عمدًا حسب سياسة المنتج.

### النظام العام
- Roles حقيقية (`TEACHER` / `STUDENT`) مطبّقة في الـ **Backend** عبر `middleware/auth.js` (`authenticate`, `authorize`, `ensureSelfStudent`) — وليس فقط بإخفاء أزرار في الواجهة.
- كل الصفحات محمية؛ أي مستخدم غير مسجّل يُحوَّل لصفحة تسجيل الدخول.

### الحسابات والدخول
- Login بالبريد/كلمة المرور (bcrypt + JWT)، ومحاولات الدخول محمية بـ Rate Limiting.
- **QR Code حقيقي لكل طالب**: توليد، عرض، تحميل، طباعة، إعادة توليد — عبر مكتبة `qrcode` وربط حقيقي بحساب الطالب (`/qr-login/:token`) يصدر جلسة JWT حقيقية.
- المدرس يدير الطلاب بالكامل: إنشاء، تعديل، حذف، تعطيل/تفعيل، بحث وفلترة، إعادة تعيين كلمة مرور.

### Teacher Dashboard
- إحصائيات حقيقية (`/api/teacher/dashboard`): عدد الطلاب/الكورسات/الحصص/الفيديوهات/الواجبات/الاختبارات/الملفات/المشاهدات، آخر الطلاب نشاطًا، آخر التسليمات، عدد العناصر التي تحتاج تصحيحًا.

### Courses + Content Isolation (القاعدة الأهم في المشروع)
- كل فيديو/واجب/ملف/اختبار يُنشأ من داخل كورس يُربط بـ `courseId` في قاعدة البيانات ولا يظهر تلقائيًا في أي قسم عام.
- قسم "الفيديوهات العامة" (`getGeneralVideos`) يستثني صراحة أي فيديو له `courseId`.
- استعلامات الطالب (`studentContentController`) تُبنى بحيث لا يستطيع الطالب استقبال أي محتوى من كورس غير مسجّل فيه، حتى بمحاولة النداء المباشر على الـ API (السلوك: 404 وليس فقط إخفاء في الواجهة) — تم اختبار هذا المنطق في المتحكمات.

### Videos
- رفع حقيقي، تحديد Visibility (الكل/صف/مجموعة/طلاب محددون)، تاريخ بداية وانتهاء صلاحية.
- **التحقق من الانتهاء والصلاحية يحدث في الـ Backend** (`fileController.streamVideo`) عند كل طلب تشغيل، وليس فقط في الواجهة، مع دعم HTTP Range للفيديوهات الكبيرة.
- Video Analytics حقيقي: عدد المشاهدات، من شاهد ومن لم يشاهد، آخر مشاهدة، تقدّم كل طالب.
- Comments على الفيديو (كتابة، ردود، إخفاء/حذف من المدرس، حماية أساسية من XSS/طول النص).

### Lessons / Homework / Materials
- Lessons مرتبطة اختياريًا بكورس، بفيديو/ملفات/واجب خاص بها، واستهداف صف/مجموعة/طلاب محددين.
- Homework: موعد نهائي، السماح بالتسليم المتأخر (إعداد قابل للتحكم)، تسليم بنص/ملف، تصحيح ودرجات وملاحظات، إشعار فوري للطالب بعد التصحيح.
- Materials/PDF: قراءة داخل المنصة أو تحميل حسب `allowDownload`، وصول محمي بالكامل (لا روابط عامة، لا Path Traversal).

### Exams
- بناء اختبار بأسئلة اختيار من متعدد ومقالية، عدد محاولات أقصى، درجة نجاح، توقيت بداية/نهاية، مدة زمنية.
- أداء الاختبار: عرض الأسئلة، مؤقّت حقيقي بعدّ تنازلي، تنقل بين الأسئلة، **حفظ كل إجابة فور تغييرها** (لا فقدان بيانات عند انقطاع الاتصال)، تسليم تلقائي عند انتهاء الوقت.
- تصحيح تلقائي فوري للاختيارات، وتحويل الأسئلة المقالية لقائمة تصحيح لدى المدرس، مع إعادة حساب الدرجة الكلية وإشعار الطالب بعد اكتمال التصحيح.
- Exam Analytics: عدد من دخل/لم يدخل/أكمل، المتوسط، أعلى وأقل درجة، نسبة النجاح، نتيجة كل طالب.

### Announcements / Notifications
- إعلانات باستهداف (الكل/صف/مجموعة/طلاب محددين).
- نظام إشعارات حقيقي مركزي (`notificationService`) يُطلق تلقائيًا عند: إضافة فيديو/واجب/اختبار/ملف/إعلان، تصحيح واجب أو اختبار، تسليم واجب، أو وجود أسئلة تحتاج تصحيحًا — لكل من الطالب والمدرس حسب الحدث.

### Teacher Profile + Platform Appearance
- ملف شخصي كامل للمدرس مع روابط تواصل اجتماعي اختيارية (Facebook, Instagram, YouTube, TikTok, Telegram, WhatsApp, X, LinkedIn, Website).
- إعدادات مظهر المنصة (اسم المنصة، الألوان الأساسية...) محفوظة في قاعدة البيانات، وتُطبَّق فعليًا كـ CSS Variables حيّة في الواجهة عند كل تحميل.

### Search
- بحث حقيقي في لوحة المدرس عبر الطلاب/الكورسات/الفيديوهات/الحصص/الواجبات/الاختبارات/الملفات/الإعلانات.
- بحث الطالب مقيّد بنفس قواعد الرؤية (Visibility) المطبّقة على باقي المحتوى.

### الأمان
- bcrypt (cost 12)، JWT في httpOnly cookie، Helmet، CORS مقيّد بالـ origin، Rate Limiting عام + أشد على تسجيل الدخول.
- لا روابط ملفات عامة إطلاقًا — كل وصول لملف يمر بفحص صلاحية حقيقي في الباك إند (`fileController`)، مع حماية من Path Traversal.
- Multer مع تحقق من نوع وحجم الملف لكل نوع محتوى (فيديو/PDF/صورة/تسليم واجب).
- تعقيم أساسي (XSS) وتحديد طول التعليقات لمنع الـ Spam.
- رسائل خطأ عامة في تسجيل الدخول (لا تكشف وجود البريد من عدمه).

### الواجهة (UI/UX)
- Sidebar + Topbar متجاوبين، القائمة تتحول لـ Hamburger Menu على الموبايل.
- Loading / Error / Empty states في كل صفحة تقريبًا (لا شاشات بيضاء عند فشل أي API).
- Modals للإنشاء والتعديل، Toast Notifications (react-hot-toast)، Tables و Cards منظمة.

## 🚀 التشغيل محليًا

### 1) قاعدة البيانات
أنشئ قاعدة بيانات PostgreSQL (Neon / Supabase / Railway / محليًا).

### 2) Backend
```bash
cd backend
cp .env.example .env
# عدّل DATABASE_URL و JWT_SECRET
npm ci
npm run prisma:migrate
npm run seed        # ينشئ أول حساب مدرس من بيانات .env
npm run dev          # http://localhost:5000
```

### 3) Frontend
```bash
cd frontend
npm ci
npm run dev    # http://localhost:5173
```

سجّل الدخول ببيانات `SEED_TEACHER_EMAIL` / `SEED_TEACHER_PASSWORD`.

## 🆕 تحديثات إضافية (بعد أول تشغيل فعلي)

> **تنبيه الحالة الحالية — 2026-10-03:** سجل التحديثات التالي تاريخي وقد يحتوي خطوات قديمة. التنفيذ الحالي يستخدم `GROQ_API_KEY` و`AI_MODEL` لمساعد الطالب فقط. Teacher AI وصفحات رفع المنهج غير متاحة حسب سياسة المنتج. إعدادات `ANTHROPIC_API_KEY` و`GOOGLE_AI_API_KEY` وميزة `pdf-parse` ليست جزءًا من الإعداد الحالي. لا تنفّذ أوامر Prisma المنسوخة من السجل التاريخي؛ راجع `docs/environment.md` وملفات migrations الحالية.

### إصلاحات
- **صورة QR كانت لا تظهر (Broken Image)**: السبب إن مفيش أي route كان بيقدّم ملفات `/uploads/qrcodes/` للمتصفح. تم إضافة `express.static` لمجلد QR فقط في `server.js`، وتحديث `vite.config.js` بإضافة `/uploads` للـ proxy. باقي الملفات (فيديوهات/PDFs) لسه بتتقدّم بس عن طريق `/api/files/...` المحمي، مش عن طريق المسار المباشر.
- **فيديو قديم بيانه موجودة والملف مش موجود**: ده سببه إن ملفات الرفع (`backend/uploads/`) بتتخزن **جوه مجلد المشروع نفسه على القرص**، لكن بيانات قاعدة البيانات محفوظة في PostgreSQL بشكل منفصل. لو استبدلت مجلد المشروع بالكامل بنسخة جديدة (زي فك ضغط zip جديد فوق القديم)، بتضيع الملفات الفعلية لكن الصفوف في القاعدة تفضل موجودة — فتظهر كأنها "موجودة" في الواجهة لحد ما تحاول تشغّلها. **الحل الدائم**: لما تحمّل نسخة كود جديدة، انسخ بس ملفات الكود ومتلمسش مجلد `backend/uploads/` القديم، أو انقله يدويًا للنسخة الجديدة قبل التشغيل. تم كمان إضافة زرار **حذف** لأي فيديو (عام أو داخل كورس) عشان تقدر تمسح أي سجل قديم بيانه تالف بسهولة.

### ميزات جديدة

**1) الصفوف الدراسية بقت Dropdown ثابت** (بدل كتابة حرة): أي مكان فيه اختيار "صف" (إنشاء طالب، إنشاء كورس، استهداف إعلان، منهج المساعد الذكي) بقى قائمة منسدلة موحّدة من 12 صف (من الأول الابتدائي للثالث الثانوي)، معرّفة في مكان واحد (`frontend/src/constants/grades.js`) — لو عايز تغيّر القائمة أو تضيف/تحذف صفوف، عدّل هنا بس وهتتحدث في كل الصفحات تلقائيًا.

**2) المساعد الذكي (AI Study Assistant) — سجل تاريخي لإصدار سابق؛ ليس وصفًا للحالة الحالية:**
- صفحة جديدة للمدرس **"منهج المساعد الذكي"**: بيكتب فيها محتوى شرح لكل صف (نص حر — أهم نقاط المنهج).
- صفحة جديدة للطالب **"المساعد الذكي"**: بيختار الصف (مع تمييز صفه هو تلقائيًا)، وبعدين بيدردش مع المساعد.
- **المساعد ميعتمدش إلا على المحتوى اللي المدرس كتبه لنفس الصف** — لو السؤال برّه المنهج المتاح، بيقول للطالب كده صراحة.
- **المساعد بيشرح المفهوم لكن ميديش إجابة نهائية جاهزة لسؤال واجب/امتحان** — عن طريق تعليمات صارمة في الـ System Prompt.

⚠️ **صراحة مهمة عن حدود الميزة دي:**
- هي "داخل المنصة" فعلًا (مفيش تحويل لموقع خارجي، والطالب بيتكلم معاها من نفس الواجهة) — لكن **تقنيًا بتستخدم Anthropic API من الخلفية** عشان تولّد الردود؛ محدش بيشوف ده غير السيرفر بتاعك.
- **لازم تحصل على مفتاح API خاص بيك** من https://console.anthropic.com (فيه استخدام مجاني محدود شهريًا)، وتحطه في `.env` باسم `ANTHROPIC_API_KEY`. من غير المفتاح ده، الميزة هتظهر رسالة "غير مفعّلة حاليًا" للطالب بدل ما تكسر.
- قاعدة "ميديش إجابة جاهزة" دي **تعليمات للنموذج مش قفل تقني 100%** — يعني في حالات نادرة ممكن الطالب يقنعه يديله إجابة مباشرة بصياغة معينة. مفيش نموذج AI بيضمن التزام مطلق 100% بتعليمات كده، لكن دي أفضل ممارسة متاحة حاليًا.

الخطوات أعلاه تصف إصدارًا سابقًا. لا تنشئ migration جديدًا لهذه الجداول ولا تعتبر تعليماتها متطلبات حالية. توجد في سجل المشروع migration أقدم باسم `20260929193000_remove_email_verification` تحذف جدول رموز التحقق وعمود `users.emailVerifiedAt`؛ لم أعدّلها ولم أطبّق أي migration على قاعدة بيانات. لا تطبّق migrations المعلّقة على إنتاج قبل مراجعتها والتأكد من أن البيانات قابلة للإزالة. حاوية Backend لا تطبّق migrations عند البدء افتراضيًا؛ شغّل `npm run prisma:deploy` بعد المراجعة أو اضبط `MIGRATE_ON_START=true` فقط بعد مراجعة كل migration معلّقة.

## 🕰️ سجل تاريخي: رفع PDF للمنهج (الميزة غير متاحة حاليًا)

- صفحة "منهج المساعد الذكي" بقت تسمح برفع **ملف PDF حقيقي** بدل الاكتفاء بنص مكتوب يدويًا.
- الـ Backend بيفتح الملف فعليًا (مكتبة `pdf-parse`) ويستخرج **كل النص اللي جواه**، ويحفظه كمحتوى المنهج — فلو طالب سأل سؤال، المساعد الذكي بيرجع فعليًا لنص الـ PDF اللي رفعته مش لاسم الملف بس.
- تقدر ترفع ملف PDF، أو تكتب ملاحظات إضافية يدوية، أو الاثنين مع بعض — بيتضافوا لبعض.
- هذه الخطوة تاريخية؛ `pdf-parse` غير مستخدمة في التنفيذ الحالي.

⚠️ ملاحظة: لو الـ PDF عبارة عن صور ممسوحة ضوئيًا (Scanned) من غير نص حقيقي جواه، الاستخراج هيرجع فاضي أو ناقص — لازم يكون PDF نص حقيقي (مكتوب من Word مثلًا)، مش صورة.

## 🕰️ سجل تاريخي: تجربة Google Gemini (غير مستخدمة حاليًا)

المساعد الذكي دلوقتي بيستخدم **Google Gemini** بدل Anthropic — عنده Free Tier فعلي وسخي (آلاف الطلبات يوميًا) **من غير أي بطاقة بنكية أو دفع**.

### خطوات التفعيل (مجانية بالكامل):
1. روح على https://aistudio.google.com/apikey وسجّل دخول بحساب Google عادي.
2. اضغط "Create API Key" وانسخ المفتاح.
3. في ملف `.env` جوه `backend`، حط المفتاح في `GOOGLE_AI_API_KEY="..."`.
4. أعد تشغيل السيرفر (`npm run dev`).

مفيش أي تعديل تاني مطلوب — باقي الكود (المنهج، اختيار الصف، منع الإجابات الجاهزة) اشتغل بنفس الطريقة بالظبط.

## 🆕 إصلاح خطير جدًا: السيرفر كان بيكرّش بالكامل عند أي خطأ

### السبب الجذري
كل الـ Controllers في المشروع كانت مكتوبة كـ `async function` من غير `try/catch`. في Node.js (من الإصدار 15 فأعلى)، أي خطأ غير متوقّع جوه دالة async بيتحول لـ "Unhandled Promise Rejection" — والسلوك الافتراضي إن Node بيوقف العملية كلها فورًا. يعني خطأ صغير في request واحد (زي طالب دوس "بدء الاختبار" مرتين بسرعة) كان بيوقف **السيرفر بالكامل**، فكل الطلاب والمدرس بيشوفوا "Unable to reach the server" لحد ما حد يعمل تعديل في ملف عشان `nodemon` يعيد التشغيل.

### الحل (اتطبّق في كل المشروع، مش مكان واحد)
1. ملف جديد `backend/src/utils/asyncHandler.js` — بيلف أي handler ويحوّل أي خطأ لرسالة JSON مفهومة للمستخدم بدل ما يكرّش السيرفر.
2. **تم تطبيقه على كل الـ Routes في المشروع بالكامل** (كل ملفات `backend/src/routes/*.js`) — كل نقطة API دلوقتي محمية.
3. طبقة أخيرة في `server.js`: إذا وقع خطأ غير معالج، يوقف السيرفر بأمان ويغلق الاتصالات حتى يعيد مشرف العمليات تشغيله بدل الاستمرار بحالة غير موثوقة.
4. إصلاح السبب الأصلي في `examController.js`: لو طالب بدأ اختبار وهو أصلاً عنده محاولة شغّالة (رفرش الصفحة، دبل كليك)، النظام بيرجّعله نفس المحاولة بدل ما يحاول يعمل واحدة جديدة تتعارض معاها.

**النتيجة**: أخطاء الطلبات المتوقعة تمرّ إلى معالج الأخطاء العام؛ أخطاء العملية غير المعالجة تؤدي إلى إيقاف منظم، لذلك يجب تشغيل الخادم تحت مشرف عمليات يعيد تشغيله.

## 🆕 إصلاحات كبيرة: ظهور الكورسات + عزل المحتوى + تحديد الصف عند الرفع

### 🔴 السبب الحقيقي وراء "الكورس ومحتواه مش بيظهر لأي طالب"
فورم إنشاء كورس كان بيبعت العنوان والوصف والصف بس — **من غير ما يسجّل أي طالب فيه فعليًا**. والطالب مبيشوفش كورس إلا لو فيه تسجيل (Enrollment) حقيقي له في قاعدة البيانات. يعني كل كورس اتعمل قبل كده كان بيتعمل "يتيم" من غير أي طالب مربوط بيه، فمكانش هيظهر لحد أبدًا — ومعاه طبعًا كل محتواه (فيديوهات، واجبات، ملفات، اختبارات).

**الحل:**
- فورم إنشاء كورس بقى فيه قائمة تحديد الطلاب اللي هيتسجّلوا فيه (مع زرار "تحديد كل طلاب الصف ده" للسرعة)، وبيحذّرك لو حاولت تعمل كورس من غير ما تختار حد.
- زرار جديد **"إدارة الطلاب المسجّلين"** في صفحة أي كورس (حتى القديم) — يقدر يضيف أو يشيل طلاب في أي وقت. **استخدمه دلوقتي على الكورسات اللي عملتها قبل كده عشان تظهر لطلابها.**

### 🔒 عزل الواجبات والملفات العامة (نفس مبدأ الفيديوهات)
كان فيه ثغرة: صفحة "الواجبات" و"الملفات" العامة كانت بتعرض واجبات/ملفات الكورسات كمان مع العامة، بدل ما تقتصر على العام بس. اتصلحت — دلوقتي كل قسم بيعرض بس اللي يخصّه، مطابق تمامًا لسلوك الفيديوهات.

### 🎯 تحديد "لمين يظهر المحتوى" عند الرفع
كل فورم رفع (فيديو، واجب، ملف، اختبار) — سواء عام أو جوه كورس — بقى فيه قائمة اختيار: **كل الطلاب / صف معيّن / مجموعة معيّنة**، بدل ما كان مربوط دايمًا على "كل الطلاب".

### 🖱️ المودال (النافذة المنبثقة)
دلوقتي بتتقفل بزرار X بس، مش بالضغط في أي مكان برّه.

### 📚 ربط الاختبار بكورس
فورم إنشاء اختبار بقى فيه قائمة اختيار الكورس، وجدول الاختبارات بيوضّح اسم الكورس (أو "عام") لكل اختبار.

## ⏭️ اللي اتأجّل للمرحلة الجاية (عشان محتاج وقت كافي يتعمل صح)

## 🆕 إصلاحات دقّة العزل + تبسيط التسجيل

### 🔒 عزل صفحات الطالب الرئيسية عن محتوى الكورسات

2. **`SEED_TEACHER_PASSWORD`**: 10 أحرف على الأقل، ومفيش كلمة مرور افتراضية. بعد أول دخول غيّرها من صفحة "الملف الشخصي".
3. **ملف `.env` سري**: ما تبعتوش ولا ترفعه على GitHub ولا تحطه في زيب تشاركه (فيه `.gitignore` جاهز). لو اتشارك قبل كده، غيّر `JWT_SECRET` و`GROQ_API_KEY` وباسورد قاعدة البيانات.
4. **`UPLOAD_DIR`** (اختياري): مسار ثابت خارج المشروع للملفات المرفوعة.
5. **`TRUST_PROXY=1`**: فعّله فقط لو السيرفر شغّال ورا reverse proxy (nginx / Render / Railway …).
6. لتثبيت الاعتماديات من ملفات القفل الحالية: `cd backend && npm ci` ثم `cd frontend && npm ci`. عند تغيير الاعتماديات عمدًا، حدّث ملف القفل وراجع نتائج `npm audit`.
7. على الإنتاج: `NODE_ENV=production` + `CLIENT_URL=https://دومينك` + شغّل الموقع على HTTPS.
8. QR Code = مفتاح دخول الطالب. صورته بقت متاحة للمدرس فقط، ولو اتسرّبت اضغط "تجديد QR" فيبطل القديم فورًا.
9. شغّل `npm audit` في `backend` و`frontend` من وقت للتاني.

## 🆕 آخر التحديثات

- **صورة للفيديو (Thumbnail):** المدرس يرفع صورة اختيارية لأي فيديو (عام / داخل كورس / فيديو شرح واجب) وتظهر للطالب قبل التشغيل. الصور (الكورسات، الفيديوهات، الشعار، الصور الشخصية) بتتقدّم من `/uploads/images` — لو بتستخدم nginx/Vercel proxy لازم تمرّر `/uploads` للـ backend زي `/api`.
- **مشغّل فيديو جديد** (`components/common/VideoPlayer.jsx`): تشغيل/إيقاف، رجوع/تقديم 10 ثواني، شريط تقدّم، صوت، سرعة، ملء الشاشة. اختصارات: `Space/K` تشغيل، `←/→` (أو `J/L`) ±10 ثواني، `↑/↓` الصوت، `M` كتم، `F` ملء الشاشة. على الموبايل: دبل-تاب على يمين/يسار الفيديو = ±10 ثواني.
- **المدرس يقدر يشغّل فيديوهاته** (معاينة زي ما الطالب بيشوفها) — قبل كده مكانش فيه مشغّل في صفحات المدرس.
- **فيديو شرح للواجب:** من صفحة الواجبات العامة ومن تبويب الواجبات داخل الكورس (زرار «الفيديوهات» لكل واجب).
- **رفع الـ PDF:** ما بقاش بيتم رفض PDF بسبب أول بايتات الملف (كانت بترفض ملفات PDF سليمة).
- **الاختبارات:** حالة النجاح/الرسوب بقت محسوبة من مكان واحد للطالب والمدرس، وبدون «درجة نجاح» مش بيظهر راسب. المدرس يفتح إجابات كل طالب ويحدد درجة الأسئلة المقالية، والطالب بيشوف النتيجة بعد التصحيح.
- **الملف الشخصي للطالب:** الاسم، الصورة، رقم الهاتف، رقم ولي الأمر.

## 🛠️ جولة إصلاحات جاهزية الإنتاج (بناءً على تقرير المراجعة)

هذا القسم يوثّق بالضبط إيه اللي اتعمل فعليًا في الكود، وإيه اللي لسه محتاج منك خطوة يدوية. **الهدف الأمانة العلمية، مش الادّعاء بمشروع "كامل 100% بدون أي مشكلة" — محدش يقدر يضمن ده فعليًا لأي مشروع حقيقي.**

### ✅ اتصلح فعليًا في الكود
- **حذف `backend/.env` نهائيًا** من أي نسخة هتتبعت — ملف `.env.example` بديل كامل بكل المتغيرات اللازمة وشرح كل واحد.
- **تخزين سحابي حقيقي (S3-compatible)**: `services/storageService.js` جديد يشتغل مع AWS S3 / Cloudflare R2 / Backblaze B2 / Supabase Storage / MinIO — بس بتغيير متغيرات البيئة (`STORAGE_DRIVER=s3` وباقي `STORAGE_*`). لو سبتها فاضية، كل حاجة شغالة زي الأول بالضبط (تخزين محلي) — صفر مخاطرة على الإعداد الحالي.
  - الفيديوهات والملفات الخاصة بتتقدّم عبر رابط موقّع (Signed URL) قصير العمر بعد التحقق من الصلاحية.
  - الصور بتتقدّم من رابط عام (Public URL) أو CDN.
  - حذف فيديو بيمسح النسخة من الباكت (مش بس من الديسك المحلي).
- **تحسين الصور تلقائيًا**: أي صورة بترفعها (غلاف كورس، صورة مصغّرة، صورة شخصية، شعار) بتتحول تلقائيًا لـ WebP وتتصغّر لحد أقصى 1600px (الـ GIF المتحرك مستثنى عشان الحركة متضيعش).
- **Logging حقيقي**: `winston` بيسجّل كل خطأ/تحذير في ملفات يومية (`backend/logs/`) بدل `console.log` اللي بيختفي مع أي إعادة تشغيل، بالإضافة لسجل لكل Request (method/path/status/مدة).
- **Pagination**: قائمة الطلاب وقائمة الإعلانات بقت مقسّمة صفحات (`?page=&limit=`) بدل استرجاع كل الصفوف مرة واحدة — أهم قائمتين بيكبروا مع الوقت.
- **اختبارات آلية** (`backend/tests/`): تشمل النتائج والصلاحيات والتعامل مع أخطاء قاعدة البيانات وإعدادات المنصة ورؤية المواد. شغّلها بـ `npm test` بعد `npm ci`.
- **CI (GitHub Actions)**: `.github/workflows/ci.yml` بيشغّل الاختبارات و build الفرونت إند تلقائيًا على أي push/PR.
- **Docker**: `Dockerfile` لكل من الباك إند والفرونت إند + `docker-compose.yml` في الجذر لتشغيل الاثنين مع بعض على أي VPS بأمر واحد.

### ⚠️ لازم تعمله إنت بنفسك (برا حدود الكود تمامًا)
1. **دوّر كل الأسرار اللي كانت في الـ `.env` المرسل قبل كده**: باسورد Supabase، `JWT_SECRET`، `GROQ_API_KEY`، باسورد حساب المدرس — من لوحة تحكم كل خدمة. محدش، أنا ولا غيري، يقدر يعمل ده غيرك لأنه محتاج وصول لحساباتك.
2. **لو هتستخدم التخزين السحابي**: اعمل حساب/باكت (Cloudflare R2 أرخص خيار غالبًا لمشروع بالحجم ده) واحصل على مفاتيح الوصول، وحطها في `.env`.
3. ملفات القفل لكل من `backend` و`frontend` محدثة؛ استخدم `npm ci` لتثبيت متكرر. Prisma CLI ضمن اعتماديات التشغيل. حاوية Backend لا تطبّق migrations تلقائيًا افتراضيًا؛ استخدم `MIGRATE_ON_START=true` فقط بعد مراجعتها.
4. **اختر أداة مراقبة أخطاء خارجية** (Sentry مثلًا) لو حبيت تضيفها فوق الـ logging المحلي — مجرد إضافة transport واحد لـ `utils/logger.js`.

### 📌 حاجات معروفة لسه محدودة (مش هخبيها)
- **QR Codes** لسه بتتخزن محليًا بس (مش على السحابة) حتى مع تفعيل `STORAGE_DRIVER=s3` — حجمها صغير ومخاطرتها أقل، بس لو انتقلت لاستضافة بديسك مؤقت هتتولّد تاني أول ما أي طالب يحتاجها (زرار "تجديد QR").
- الـ Pagination اتضاف لأهم قائمتين بس (الطلاب، الإعلانات) — باقي القوائم (تسليمات واجب/اختبار معيّن) محدودة بحجم الفصل فعليًا، فمش أولوية دلوقتي، بس سهل تتضاف بنفس الطريقة (`utils/pagination.js`) لو احتجتها.
- الاختبارات الآلية بتغطي المنطق الحرج (النتائج، الصلاحيات) مش كل السطور في المشروع — تغطية 100% مش هدف واقعي ولا مفيد لمشروع بالحجم ده.
